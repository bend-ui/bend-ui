# Colors

The design preset exposes semantic color tokens for text, fills, and strokes. Prefer semantic names so components continue to work when the active theme changes.

## Use semantic colors

Generated Panda elements accept semantic token names as style props:

```tsx
import { Box, Stack } from 'styled-system/jsx';

export function StatusPanel() {
  return (
    <Box
      backgroundColor="fill.weak"
      color="text"
      borderColor="stroke.weak"
      borderWidth="1px"
      borderRadius="md"
      padding="6"
    >
      <Stack gap="2">
        <strong>System status</strong>
        <span>All services are operational.</span>
      </Stack>
    </Box>
  );
}
```

## Style a native element

Use the generated `css` helper when a JSX element is not appropriate:

```tsx
import { css } from 'styled-system/css';

export function MutedNote() {
  return <p className={css({ color: 'text.weak' })}>Updated a minute ago</p>;
}
```

## Use component variants

Adapter components already map their variants to semantic colors. Choose the variant that expresses intent instead of overriding its fill directly.

```tsx
import { Button } from '@bend-ui/base-ui';
import { Flex } from 'styled-system/jsx';

export function Actions() {
  return (
    <Flex gap="3">
      <Button variant="primary">Confirm</Button>
      <Button variant="secondary">Cancel</Button>
      <Button variant="danger">Delete</Button>
    </Flex>
  );
}
```

## Guidelines

- Use text tokens for foreground content, fill tokens for backgrounds, and stroke tokens for borders.
- Prefer semantic tokens over literal palette values in product UI.
- Do not use color as the only way to communicate state.
- Check focus, hover, disabled, and high-contrast states when extending component styles.

See [Design Tokens](/docs/foundation/design-tokens) for configuration and extension examples.
See [Theme Personalities](/docs/foundation/themes) for the named OKLCH ramps and their semantic mappings.
