# Button

Use `Button` for actions such as submitting a form, confirming a choice, or opening a surface.

## Live example

<ButtonReferenceExample />

Use Enter or Space on an action and watch the result count. The icon-only Add item action has a visually hidden label; unavailable actions are skipped during keyboard navigation. The Composed action uses Base UI native render composition and retains button semantics. The example inherits the document color mode.

## Import

```tsx
import { Button } from '@bend-ui/base-ui';
```

## Basic usage

<ComponentPreview example="button" />

```tsx
import { Button } from '@bend-ui/base-ui';

export function Example() {
  return <Button variant="primary">Save changes</Button>;
}
```

## Hierarchy and treatment

```tsx
import { Button } from '@bend-ui/base-ui';
import { Flex } from 'styled-system/jsx';

export function Variants() {
  return (
    <Flex gap="3" flexWrap="wrap">
      <Button variant="primary">Primary</Button>
      <Button variant="secondary">Secondary</Button>
      <Button variant="tertiary">Tertiary</Button>
      <Button variant="danger">Delete</Button>
      <Button variant="inverse">Inverse</Button>
    </Flex>
  );
}
```

The existing `variant` prop carries hierarchy and contextual treatment; these are not separate runtime axes.

| Value       | Intent                                 |
| ----------- | -------------------------------------- |
| `primary`   | Main action in a region; use sparingly |
| `secondary` | Supporting action and the default      |
| `tertiary`  | Low-emphasis action                    |
| `danger`    | Destructive action with a clear label  |
| `inverse`   | Inverse surface treatment              |

Size is independent of treatment. The shared control scale is `sm`/`md`/`lg`, with `md` as the default. `isRounded` changes shape; `isFull` fills the available width.

## Anatomy

The convenience `Button` renders these public styling slots from the `button` slot recipe, whose class namespace is `Button`:

| Part      | Export           | Purpose                                        |
| --------- | ---------------- | ---------------------------------------------- |
| `root`    | `Button.Root`    | Interactive Base UI button and recipe provider |
| `label`   | `Button.Label`   | Action text                                    |
| `icon`    | `Button.Icon`    | Leading or trailing icon                       |
| `spinner` | `Button.Spinner` | Loading presentation                           |

Use the compound exports when you need to arrange the content yourself:

```tsx
import { Button } from '@bend-ui/base-ui';

export function ComposedButton() {
  return (
    <Button.Root variant="secondary" size="md">
      <Button.Icon aria-hidden="true">+</Button.Icon>
      <Button.Label>Add item</Button.Label>
    </Button.Root>
  );
}
```

The compound root supplies recipe context; it does not add the convenience component's loading indicator or normalize `isDisabled`. Use native `disabled` on `Button.Root` and compose busy presentation explicitly.

## Disabled and loading states

```tsx
import { Button } from '@bend-ui/base-ui';
import { Flex } from 'styled-system/jsx';

export function States() {
  return (
    <Flex gap="3">
      <Button disabled>Unavailable</Button>
      <Button isLoading>Saving</Button>
    </Flex>
  );
}
```

`isLoading` sets `aria-busy` and renders the spinner slot. It does not disable the action or provide an animated spinner graphic. Keep the action label and set `disabled` as well when repeat activation must be prevented.

| State          | Current styling hook                     | Responsibility                                                   |
| -------------- | ---------------------------------------- | ---------------------------------------------------------------- |
| Hover          | `_hover`                                 | Recipe presentation                                              |
| Pressed        | `_active`                                | Recipe presentation                                              |
| Keyboard focus | `_focusVisible`                          | Preserve a visible focus indicator                               |
| Disabled       | `_disabled`, including `[data-disabled]` | Native disabled behavior plus recipe presentation                |
| Loading        | `[data-loading]` on the spinner          | Convenience component renders the slot and sets root `aria-busy` |

These are styling hooks, not instructions to force interaction states by adding DOM attributes.

## Icons

Pass icons with `icon` or `iconEnd`:

```tsx
import { Button } from '@bend-ui/base-ui';

export function AddButton() {
  return <Button icon={<span aria-hidden>+</span>}>Add item</Button>;
}
```

For an icon-only action, supply its accessible name as `IconButton` children:

```tsx
import { IconButton } from '@bend-ui/base-ui';

export function AddIconButton() {
  return (
    <IconButton icon={<span aria-hidden="true">+</span>}>Add item</IconButton>
  );
}
```

The label is visually hidden, and the icon is decorative. A tooltip can supplement the name but does not replace it. `IconButton` shares Button variants, native composition/ref props, and the `isDisabled`/`isLoading` aliases. Busy state does not implicitly disable either component.

## Native composition

Keep Base UI's `render` and `nativeButton` model when composing a custom element. Native `<button>` is the preferred default. A non-native action needs `nativeButton={false}` so the primitive supplies button semantics and keyboard activation:

```tsx
<Button render={<span />} nativeButton={false} onClick={runAction}>
  Run action
</Button>
```

This changes the rendered element, not the control's purpose. Use a real link for navigation. `IconButton` accepts the same composition props and HTMLElement ref. For an unavailable native button, use `disabled` or `isDisabled`. The opt-in `focusableWhenDisabled` keeps it focusable while Base UI prevents activation; explain the reason for unavailability nearby.

## Full width

```tsx
import { Button } from '@bend-ui/base-ui';

export function SubmitButton() {
  return (
    <Button type="submit" variant="primary" isFull>
      Submit
    </Button>
  );
}
```

## Custom styling

Use the generated `css` helper to add application-specific styling:

```tsx
import { Button } from '@bend-ui/base-ui';
import { css } from 'styled-system/css';

export function AlignedButton() {
  return <Button className={css({ alignSelf: 'start' })}>Continue</Button>;
}
```

## API

`Button` accepts Base UI button props plus Bend UI recipe variants.

| Prop         | Type                                                              | Default       | Purpose                                        |
| ------------ | ----------------------------------------------------------------- | ------------- | ---------------------------------------------- |
| `variant`    | `'primary' \| 'secondary' \| 'tertiary' \| 'danger' \| 'inverse'` | `'secondary'` | Visual emphasis                                |
| `size`       | `'sm' \| 'md' \| 'lg'`                                            | `'md'`        | Control size                                   |
| `isFull`     | `boolean`                                                         | `false`       | Fill the available width                       |
| `isRounded`  | `boolean`                                                         | `false`       | Use a fully rounded shape                      |
| `isDisabled` | `boolean`                                                         | `false`       | Disable the action                             |
| `isLoading`  | `boolean`                                                         | `false`       | Mark the action busy and show the spinner slot |
| `icon`       | `ReactNode`                                                       | —             | Leading icon                                   |
| `iconEnd`    | `ReactNode`                                                       | —             | Trailing icon                                  |

Use a link for navigation. Use a button when activating the control changes application state or performs an action.

## Accessibility and customization

Keep a meaningful action label, preserve visible keyboard focus, and use native form props such as `type="submit"` deliberately. Verify activation with both Enter and Space in the consuming flow. Use native `disabled` when an action is unavailable; changing opacity alone does not disable a button.

[Customize a Button recipe](/docs/foundation/recipe-customization) to change visual treatment without editing component behavior. Preserve the public slots, class namespace, supported variants, and defaults for a drop-in replacement. New consumer variant values and compound rules require a consumer-owned component using the consumer-generated recipe; they do not update the published Button runtime.

This is the Base UI v0 reference contract. Existing recipe values remain deliberate; new hierarchy or treatment axes are not introduced.
